Network troubleshooting that explains itself.

GeeNet is a free Windows toolkit with two doors. Guided mode asks you two or three plain questions, then finds the fault itself — and says what every result means, what probably caused it, and what to do next. Professional mode keeps every classic tool within one keypress: ping, traceroute, DNS, ARP, routes, packet loss, MTU, Winsock and TCP/IP resets.

No installation. No account. No internet needed to run. Nothing is sent anywhere.

The problem GeeNet is trying to solve

When the internet breaks, the person in front of the computer is usually left alone with two bad options: guess, or call somebody. Windows itself is not much help either.

What goes wrong today

  • “No internet access” — and nothing else. Windows knows far more than that, but it does not say it.
  • The same advice every time: restart the router, restart the computer, re-enter the Wi-Fi password. It sometimes works, which is why people keep doing it, but it teaches nothing.
  • Command-line answers. Help forums reply with ipconfig /all, netsh winsock reset or route print, and assume you know what to do with the output.
  • Guesswork repairs. People run a "network reset" as a first step instead of a last one, lose their saved Wi-Fi profiles and settings, and still do not know whether the problem was fixed or just hidden.
  • Technicians start from zero on every call, asking the same questions the computer could have answered.

What GeeNet does instead

  • Tests in the order a technician would: physical link → adapter → IP address → router → internet by IP → names → web. The first real failure is the answer.
  • Stops early. If the Wi-Fi adapter is off, testing DNS is pointless — GeeNet skips it and says why.
  • Explains every result in plain words: what was tested, why, what the result means, the likely causes, and what to do.
  • Repairs by risk tier. Safe things first (clear the DNS cache, renew the address, reconnect Wi-Fi). Disruptive things only as a clearly labelled last resort, and never without asking.
  • Checks its own work. After a repair it re-tests the affected checks, and says plainly when a repair did not help.
  • Writes it down. A plain-text report with the problem, the findings, the likely cause, what was tried, the current status and the next step.

GeeNet is honest about its limits too. It diagnoses the computer side and says so when the fault is almost certainly the router, the line or the ISP — no program on a PC can repair those, and pretending otherwise wastes people's time.

How it works

One idea runs through the whole tool: a diagnostic finding is only useful if it comes with meaning and a next step.

1

You describe the problem

15 categories, 160 real symptoms — from "the internet stopped working" to "only one app cannot connect". Nothing technical is asked of you.

2

GeeNet finds the numbers

It reads the addresses, gateway and DNS servers from Windows itself, so you never have to look them up or understand them.

3

Tests in order, then stops

Link, adapter, IP, DHCP, router, internet, names, web. The first layer that fails is the answer; everything after it is skipped and explained.

4

Repair, re-test, report

Every repair is explained before it runs, confirmed, executed, checked for its real result, and then the diagnosis is re-run.

The layers it walks through

  1. Physical link — is the cable in, is Wi-Fi connected, is the adapter switched on?
  2. Adapter and driver — does Windows see a healthy network device?
  3. IP address and DHCP — does this computer have a usable address, or a 169.254 self-assigned one?
  4. Default gateway — is there a router address, and does the router answer?
  5. Internet by address — does anything outside answer, with names not involved yet?
  6. Name resolution — can names be turned into addresses, and does a public resolver agree?
  7. Web and applications — does real HTTPS traffic work, and is one specific service being blocked?

What every result carries

  • What was tested, and why it matters
  • What the result means in plain words
  • The likely causes, in order of probability
  • What you should do next
  • Whether GeeNet can fix it itself, or only an administrator, you, or the ISP can
  • Whether a restart is needed — and GeeNet never restarts anything for you

Press T anywhere GeeNet reports a diagnosis to see the raw values behind it if you or a technician want them.

Who it is for

The person whose internet stopped

You will be asked what the problem feels like, not what a subnet mask is. At the end you get a diagnosis in sentences and, usually, one safe thing to try.

The technician on a support call

Run guided mode for the reasoning, professional mode for the raw tools, and hand over a report that already contains the configuration, the tests and what was tried.

The person who wants to understand

Every check says why it exists. GeeNet is written to teach the shape of a network while it fixes it — layers, addresses, gateways, resolvers, and what each one failing means.

Questions people ask

Anything else, ask in the GitHub issues.

What exactly do I need to run it?

Windows 10 or Windows 11, and PowerShell — version 5.1 (built into Windows) or 7 and newer. Nothing else: no Python, no Node.js, no modules to install, no account to create.

Is it really free?

Yes. It is free and the source is on GitHub, so you can read every line before you run it. There is no paid tier, no online service, and no data collection of any kind.

Windows says "running scripts is disabled on this system". What now?

That is a Windows safety setting for scripts in general, not a problem with GeeNet. Double-click GeeNet.bat — it starts PowerShell with the right option only for this run — or use:
powershell -NoProfile -ExecutionPolicy Bypass -File GeeNet.ps1

Windows showed a warning, or my browser did. Should I worry?

Files downloaded from the internet carry a marker that Windows and browsers show for every script. If you prefer, read the source on GitHub, then use the file. You can also clear the marker: right-click the file → Properties → tick Unblock → OK.

Does it need administrator rights?

No, not for diagnostics. Every check works as a standard user. A few repairs change system settings (a Winsock reset, a TCP/IP reset, disabling an adapter), and those will tell you they need Administrator rights before they run. You can also start GeeNet with GeeNet.bat -Admin or from menu option [6].

Will it change my computer without asking?

No. Diagnostics only read. Every repair is explained, then confirmed by you, then run — one at a time — and afterwards GeeNet re-tests and reports the real result. High-impact repairs such as a full network reset ask an extra time and warn you what you will lose.

Will it restart my computer?

Never. Some repairs (TCP/IP reset, network reset) only take full effect after a restart, and GeeNet will tell you that clearly — but it will not restart anything. That decision stays with you.

Does it send my information anywhere?

No. GeeNet runs entirely on your computer and needs no internet connection to start. Nothing is uploaded, and there is no telemetry and no analytics.

What does it put on my disk?

Reports and a session log, as plain text files, in the reports folder next to the script and in your temporary folder. GeeNet prints the paths on screen. Delete them whenever you like — nothing else is left behind, and no registry keys are added.

What is in the reports? Could they leak something private?

Network configuration and test results: computer name, Windows version, adapters, addresses, gateway, DNS servers, DHCP state, Wi-Fi details, routes and the tests. No passwords, no browsing history, no personal files, no Wi-Fi passwords. They are text files — open them in Notepad and read them before sending them to anybody.

How do I know the tool itself is working correctly?

Run GeeNet.bat -SelfTest. GeeNet simulates 21 different computers — healthy, cable unplugged, self-assigned 169.254 address, router dead, DNS broken, HTTPS blocked, single application failing, VPN tunnel stuck and more — and checks that it reaches the right conclusion for each one. 225 checks, about 14 seconds, and a report is written either way.

My problem is my router or my ISP. Will this help?

It will tell you that. GeeNet can prove the computer side is fine and point at the router, the line or the ISP with evidence — for example, the router answers but nothing beyond it does, or other devices on the network fail too. It will not pretend it can reboot your router or repair a line, because no program on a PC can.

Can I use it at work, or on a customer's machine?

Yes, though check your own policy first, as with any tool. GeeNet only reads configuration and runs the repairs a person chooses. It leaves no services, no startup entries and no registry settings behind.

Something is broken, or I have an idea. How do I report it?

Open an issue on GitHub. The most useful thing to attach is the self-test report and the session report from the reports folder — they contain what GeeNet saw and concluded.

Who made this

GeeNet is made by George Mwanga. It exists because of a very ordinary situation: a connection stops working, Windows says "no internet access", and the person sitting there is handed a wall of commands and left to guess. The tools were never the problem — the missing part was explaining.

So GeeNet does the part a good technician does on a support call: ask what is wrong in plain language, test the layers in a sensible order, stop when continuing makes no sense, say what the result means, fix only what can safely be fixed, and check afterwards whether it actually helped.

It is built to be usable in the places where tools usually are not: on an old laptop, on a slow connection, offline, without installing anything, and without asking the person to learn a single command.
